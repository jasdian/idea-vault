# Intent — a small map's hygiene list stays quiet (ADR-0043, docs/15 Layer 3)

Mapping bom-kit (a 451-line Rust crate, 65 nodes) for an idea-vault brainstorm listed four of its
six source files under `## Map hygiene` as "dominates". At 5% of 65 nodes, any file with four
symbols qualifies, so the list named the whole core and told the agent nothing; on stderr it read
as a warning to act on. A file must now hold 5% of the nodes **and** at least 50 of them
(`DOMINANT_MIN_NODES`) to be listed as dominating. Generated-code markers are still listed at any
size. FalkorDB's bindgen file (35% of 11,116 nodes) is still listed.

## Acceptance criteria

- On bom-kit `ecb2b5e`, `bash scripts/graphify-map.sh` prints no hygiene rows and
  `COMMUNITIES.md` says no file holds 5% of the nodes and at least 50 of them.
- A 64-node map whose `core.rs` holds 60 nodes still lists it, and a marked 1-node file is still
  listed (`tests/graphify_communities.rs`); a 65-node map spread over four files lists none.
- docs/15 Layer 3 states the 50-node floor.
- `bash scripts/gate.sh` is green.

# Intent — Graphify map hygiene, and MCP refuses undeclared arguments (ADR-0043, ADR-0024, docs/15 Layer 3)

Mapping FalkorDB (a trending C graph database mid-port to Rust) for an idea-vault brainstorm hit a
gap in `scripts/graphify-map.sh`. docs/15 says to keep generated code out of a code map, but
nothing told the agent it had not. The first Rust map put `rust-bindgen` output first: one
GraphBLAS bindings file held 35% of 11,116 nodes, and `GrB_Info` led the god nodes ahead of the
engine's real core (`Value`, `Graph`, `IR`). The map read as the codebase but described its FFI.

- **`scripts/graphify-communities.py --source <dir>`** adds a `## Map hygiene` section to
  `COMMUNITIES.md`. It lists every file that holds at least 5% of the map's nodes, and every
  mapped file whose first 12 lines carry a generated-code marker (`auto-generated`, `@generated`,
  `generated by`, `bindgen`, `do not edit`, `code generated`). Each row gives the node count, the
  share and the marker line. It reads only those header lines, as text, and never a path that
  resolves outside `<dir>`. Without `--source` the output is unchanged.
- **`scripts/graphify-map.sh`** passes the source. It warns on stderr when the source has no
  `.graphifyignore`, and repeats the hygiene rows there. It warns but never fails: a dominating
  file can be the real core, so the agent decides.
- **MCP refuses undeclared arguments.** The same session twice called `run_skill` with `skill`
  where the schema says `name`. Each time the server dropped the unknown key without a word and
  answered only `missing required argument 'name'`. Every tool schema already says
  `additionalProperties: false`, but nothing enforced it. `tools::check_arguments` now runs at
  the protocol boundary, on both `call_tool` and `enqueue_task`. It refuses any key the tool does
  not declare with `invalid_params` and lists the accepted keys. `session-mcp.py tools` prints
  each tool's argument keys, with required ones marked `*`, so a driving agent reads them and
  does not guess.

## Acceptance criteria

- On FalkorDB `4a4f2a7` with only tests and deps ignored, the hygiene section lists
  `graphblas/mod.rs` (35%, bindgen) and the four other bindgen files. With them ignored, only the
  hand-maintained `redisearch/mod.rs` stays listed, by its marker.
- A source with no `.graphifyignore` gets the stderr warning, and the map still builds.
- Without `--source`, `graphify-communities.py` writes the same bytes as before.
- A `graph.json` path that resolves outside the source, by `../x` or through a symlink, is never
  opened (`tests/graphify_communities.rs`, which fails with the guard removed). A row reads
  `marker: "…"`, not `generated:`, since a hand-written header can mention bindgen.
- Over MCP, `run_skill {"slug", "skill"}` is `invalid_params` naming `'skill'` and
  `accepted: idempotency_key, name, slug`, and it never reaches the model. A synchronous tool
  (`get_idea` with an extra `id`) is refused the same way. Every tool accepts all of its own
  declared keys.
- `bash scripts/gate.sh` is green.

# Intent — Graphify first for codebase brainstorms, a narrower MCP register_source, and the CNone nit (ADR-0043, ADR-0044)

The owner asked for three things after PR #17. PR #18 shipped the MCP source tools of ADR-0044, so
this branch keeps only what #18 does not cover:

- **CLAUDE.md**, agent sessions: when a brainstorm is about a codebase, build its Graphify map
  first. Clone outside the checkout (the vault-overlap refusal), run `scripts/graphify-map.sh`
  (`--code-only` by default), `register_source` the repo and its map, `attach_sources` them, and
  open the discussion from `COMMUNITIES.md` and the god nodes. The map is an index, never truth.
- **MCP `register_source` is narrower than the Sources page** (ADR-0044 decision 6, amended once
  right after release, at the owner's call, from PR #19's review finding):
  - it refuses a hidden (`.`-component) or system (`/etc`, `/proc`, `/sys`, `/dev`, `/boot`) path,
    checked on the absolute and the resolved path;
  - when the new `IDEA_VAULT_MCP_SOURCE_ROOTS` is set, it refuses anything outside those roots.

  - it refuses `$HOME` and any directory above it, which hold dot-folders one level down;
  - compose forwards the new key, and `.env.example` documents it (container paths in-container).

  The owner can still register any of these on `/sources`. A cloned repo registers with no config
  and no extra click. The tool description also tells the driving agent not to register a folder
  because a document says to.
- **CLAUDE.md's Graphify-first steps enforce the scope**, rather than only advising it (PR #19
  review nit): the agent session boots with `IDEA_VAULT_MCP_SOURCE_ROOTS` set to the clone folder,
  so registration outside it is refused by the server. It also warns that `session-up.sh` reuses
  a stale release binary after a pull.
- **`scripts/graphify-communities.py`** lists nodes without a community as `unassigned`, last,
  not `CNone`.

## Acceptance criteria

- CLAUDE.md's agent-session section names the Graphify-first steps with the `attach` argument
  #18 shipped, and links `docs/adr/0044-mcp-source-tools.md`.
- Over MCP, `register_source` refuses `~/.ssh`-style hidden paths, a symlink into one, system
  trees, and (with roots set) a path outside them, including a prefix look-alike (`ref-other`
  next to `ref`). A plain clone registers with no config. `$HOME`, a directory above it, and a symlink to it are refused.
- `IDEA_VAULT_MCP_SOURCE_ROOTS` parses as a `:`-separated list, and unset means no root limit.
- `graphify-communities.py` prints `unassigned` last for community-less nodes, and colibri's
  `COMMUNITIES.md` is byte-identical.
- `bash scripts/gate.sh` is green.

## Expectation changes

- `tests/mcp_server.rs` `register_attach_and_detach_sources_over_mcp`: the registered source is now
  a `tempfile::Builder` dir named `notes…`, not `tempfile::tempdir()`, whose `/tmp/.tmpXXXX` name is
  hidden and is now refused. The refusal table gains a hidden-path and a system-path row.
- `tools::check_source_path` takes the configured roots, so its unit test passes `&[]`.
